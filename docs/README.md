# Pickle CLI for BlueStacks Air

macOS의 BlueStacks Air에서 실행 중인 Pickle 앱을 조작하는 **비공식 개념 검증용 CLI**입니다. 공식 Pickle API나 SDK가 아니라 Android 화면과 기본 파일 선택·저장 UI를 사용합니다.

다른 사람이 자신의 Mac과 Pickle 계정으로 실행할 수 있도록 소스로 구성했습니다. **사람이 옆에서 상태를 확인하되, 실행 중에는 키보드·마우스·앱 화면을 조작하지 않는 방식**을 전제로 합니다. 무인 운영이나 중요한 업무의 안정적인 전송 수단으로 사용하지 마세요.

## 준비물

- Apple Silicon Mac과 macOS
- BlueStacks Air, Pickle 앱, 본인의 로그인된 계정
- Python **3.9 이상**
- 사용자가 직접 켠 BlueStacks의 로컬 ADB
- 한글 등 클립보드 입력을 사용할 경우: **이미 설치된 Swift 명령줄 도구와 기존 macOS 손쉬운 사용(Accessibility) 권한**

Python 표준 라이브러리만 사용하므로 `pip install`은 필요하지 않습니다. 별도 `adb` 실행 파일도 설치하지 않습니다. CLI가 도구를 설치하거나, ADB·원격 접속을 켜거나, 인증 키를 만들거나, 새 권한을 부여하지는 않습니다.

허용된 영문·숫자·일부 기호는 ADB로 직접 입력합니다. 한글, 이모지, 줄바꿈, 그 밖의 문자는 Swift/AppKit 클립보드 경로를 사용합니다. Mac 클립보드는 실행 중 다른 복사가 없으면 원래 형식과 내용을 복원합니다. **Android 에뮬레이터 클립보드에는 입력한 텍스트가 남으며, 원래 내용으로 복원하지 않습니다.**

기준 환경은 BlueStacks Air **5.21.790.7505**, Android **13**입니다. 한국어·영어 UI 라벨을 처리합니다. 실제 앱 검증은 한국어 UI에서 했으며 영어 UI는 미검증입니다. 자세한 확인 범위는 [TESTING.md](TESTING.md)를 참고하세요.

## 빠르게 시작하기

### 1. ZIP을 풀고 패키지 폴더 열기

`pickle_cli` 폴더가 들어 있는 루트에서 실행합니다.

```sh
cd /path/to/pickle-air-cli-0.1.0
python3 -m pickle_cli --help
```

### 2. 앱 준비

1. BlueStacks Air를 실행합니다.
2. BlueStacks의 고급 설정에서 로컬 ADB를 직접 켭니다. 설정 이름과 위치는 버전에 따라 다를 수 있습니다.
3. Pickle에 로그인하고 사용할 에이전트 대화를 직접 엽니다. CLI가 다른 대화를 찾아 열지는 않습니다.
4. 기존 초안·첨부 파일을 확인하고 직접 정리합니다. 빈 입력창에서 시작하세요.
5. BlueStacks를 전면에 두고, 명령이 끝날 때까지 다른 입력이나 화면 조작을 하지 않습니다.

기본 연결 대상은 `127.0.0.1:5555`입니다. 다른 로컬 포트는 지정할 수 있지만 호스트는 항상 `127.0.0.1`입니다. 외부 주소 연결, 공유기 포트 포워딩, 네트워크 공개는 지원하지 않습니다.

### 3. 진단과 읽기

```sh
python3 -m pickle_cli doctor
python3 -m pickle_cli read --agent "에이전트 이름"
```

`doctor`는 연결·Android 버전·Swift·기존 손쉬운 사용 권한 정보를 JSON으로 출력합니다. 종료 코드만 보지 말고 `swift`와 `unicode_permission`도 확인하세요. 진단 통과가 전송·첨부·다운로드 전체의 성공을 뜻하지는 않습니다.

`read`는 **현재 대화 화면에 보이는 텍스트와 위치**만 반환합니다. 스크롤하거나 과거 기록 전체를 내보내지 않습니다.

## 명령어

### 전역 옵션

전역 옵션은 하위 명령 **앞에** 둡니다.

```sh
python3 -m pickle_cli --port 5555 --state-dir "./private-state" read --agent "에이전트 이름"
```

- `--port`: 로컬 포트. 기본값 `5555`, 허용 범위 `1024–65535`.
- `--state-dir`: 요청 기록 위치. 기본값 `~/.local/state/pickle-air-cli`. `ask`의 중복 방지 기록에 사용합니다.

새 상태 디렉터리는 권한 `0700`으로 생성합니다. 기존 폴더를 지정했다면 접근 권한은 직접 확인하세요. `read`·`ask`·`download`는 같은 포트를 사용하는 CLI끼리 동시에 실행되지 않도록 잠급니다. 이 잠금 파일은 `--state-dir`과 관계없이 기본 상태 디렉터리에 남습니다. 수동 조작이나 다른 자동화 도구까지 막지는 못합니다.

### 텍스트 질문

```sh
python3 -m pickle_cli ask \
  --agent "에이전트 이름" \
  --message "테스트 메시지입니다. 짧게 답해 주세요." \
  --timeout 120 \
  --request-id "demo-text-001"
```

`ask`는 실제 Pickle 대화에 메시지를 보냅니다. 비민감 문구로 먼저 확인하세요.

- `--agent`: 현재 열린 대화 상단에서 확인할 에이전트 이름.
- `--message`: 1–12,000자. NUL 문자는 허용하지 않습니다.
- `--timeout`: 전송 후 응답 대기 시간. 기본 120초, 허용 범위 10–600초. 사전 준비나 파일 저장에 걸리는 시간을 포함한 전체 실행 제한은 아닙니다.
- `--request-id`: 영문·숫자·밑줄·하이픈 1–80자. 생략하면 에이전트·본문·첨부 내용의 해시로 ID를 만듭니다.

기록에는 요청 ID, 해시, 상태, 갱신 시각만 남기고 메시지 본문이나 대화 로그는 저장하지 않습니다. 동일 요청 ID는 이미 기록된 상태가 무엇이든 다시 실행하지 않습니다. 기본 ID를 사용하면 같은 에이전트·본문·첨부 내용의 재실행도 차단합니다.

전송 버튼은 한 번만 누릅니다. 읽기는 재시도할 수 있지만, 오류나 응답 지연을 이유로 자동 재전송하지 않습니다. 시작 시 기존 초안·첨부가 있으면 보존하고 중단합니다. 실행 도중 오류가 나면 CLI가 작성한 초안·첨부가 남을 수 있습니다.

**시간 초과는 전송 실패가 아닙니다.** 앱과 `read`, 로컬 기록을 먼저 확인하세요. 결과가 불확실할 때 새 ID를 만들거나 기록을 지워 재시도하지 마세요. 같은 내용을 의도적으로 다시 보내려는 경우에만 기존 전송을 확인한 뒤 새로운 ID를 사용하세요.

### 첨부와 함께 질문

```sh
python3 -m pickle_cli ask \
  --agent "에이전트 이름" \
  --message "첨부한 테스트 파일을 확인해 주세요." \
  --attach "./examples/test-image.png" \
  --attach "./examples/test-data.txt" \
  --request-id "demo-files-001"
```

예시 파일은 패키지의 examples 폴더에 포함된 비민감 합성 테스트 자료입니다.

- `--attach`를 반복해서 최대 **4개**, 파일당 **8 MiB 이하**로 지정합니다.
- 허용 확장자: `.png`, `.jpg`, `.jpeg`, `.txt`, `.pdf`, `.csv`. **실제 첨부 확인은 PNG와 TXT에 한정**합니다.
- 일반 파일만 사용하며 심볼릭 링크는 거부합니다.
- Android의 작업별 `Download/pickle-cli-…` 폴더로 복사하고 SHA-256을 비교한 뒤 기본 Files 선택기로 고릅니다.
- Android 파일명에는 `01-`, `02-` 같은 순번을 붙입니다. 원래 이름이 안전한 ASCII 규칙을 벗어나면 `01-attachment-1.ext`처럼 바꿉니다. Mac 원본은 변경하지 않습니다.
- Android 작업용 파일과 중간 `.b64` 파일은 **자동 삭제하지 않습니다**. 필요하면 사용자가 직접 정리하세요.

첨부 후에는 선택기의 파일명, 복사 해시, 첨부 개수를 확인합니다. 다만 최종 첨부 표시에서 파일명을 읽을 수 없어 **전송 직전 첨부의 최종 정체성까지 검증하지는 못합니다**. 같은 개수로 파일이 바뀌는 동시 조작이나 모든 업로드 진행 상태를 감지할 수 없습니다. 실행 중에는 앱을 건드리지 마세요.

### 응답 파일 다운로드

질문과 함께 다운로드를 요청할 수 있습니다. 파일명을 알고 있다면 `--download-name`을 함께 쓰세요.

```sh
python3 -m pickle_cli ask \
  --agent "에이전트 이름" \
  --message "짧은 테스트 내용을 response.txt 파일로 만들어 주세요." \
  --download-dir "./downloads" \
  --download-name "response.txt" \
  --timeout 120 \
  --request-id "demo-download-001"
```

`--download-name`은 `--download-dir`이 있을 때만 사용합니다. 생략하면 새 응답에서 파일명으로 보이는 항목을 찾습니다. 후보가 여럿이면 중단하므로 앱을 확인하고 파일명을 직접 지정하세요.

이미 화면에 표시된 파일은 다음 명령으로 저장합니다.

```sh
python3 -m pickle_cli download \
  --agent "에이전트 이름" \
  --name "response.txt" \
  --output-dir "./downloads"
```

파일명을 길게 누르고 기본 Files 저장 화면을 거쳐 Mac으로 가져옵니다.

- `--name`과 `--download-name`은 **앱에 표시된 정확한 파일명**입니다. 다른 이름으로 바꾸는 옵션이 아닙니다.
- 이름은 영문·숫자로 시작하고 영문·숫자·점·밑줄·하이픈만 사용하는 1–120자 ASCII 이름이어야 합니다.
- 로컬에 같은 이름의 파일이 있으면 덮어쓰지 않고 중단합니다.
- 응답 파일 제한은 **16 MiB**입니다. 저장된 크기·해시의 안정성과 복사 후 해시를 확인하도록 구현되어 있습니다. 앱에 정확한 바이트 크기가 표시되면 그 값도 비교합니다.
- Android에 만든 응답 복사본도 자동 삭제하지 않습니다.

다운로드만 실패했다면 질문을 다시 보내지 마세요. 앱에 생성된 파일이 있는지 확인한 뒤 `download`로 저장을 시도하세요. 같은 파일명이 여러 번 표시되거나 UI가 바뀌면 중단할 수 있습니다. 가져온 파일은 직접 열어 크기와 내용을 확인하세요. 최신 다운로드 검증 상태는 [TESTING.md](TESTING.md)에 구분해 적었습니다.

## 결과와 오류

명령 결과는 JSON으로 출력합니다. `ask`의 주요 상태는 다음과 같습니다.

| 상태 | 의미 |
| --- | --- |
| `completed` | 화면에서 보낸 메시지와 새 응답을 확인함. 다운로드 요청이 있으면 파일 저장도 완료함 |
| `sent_wait_timeout` | 전송은 화면에서 확인했지만 대기 조건을 끝내 충족하지 못함 |
| `uncertain` | 화면에서 전송 완료를 확정하지 못함. 전송되지 않았다는 뜻은 아님 |

파일 없는 응답은 화면 변화가 약 6초 동안 멈추면 완료로 판단합니다. 공식 서버 완료 이벤트가 아니므로 긴 응답·중간 멈춤·화면 밖 텍스트는 잘못 판단하거나 일부만 읽을 수 있습니다.

종료 코드 `0`은 명령 성공, `2`는 오류, `4`는 전송 후 대기 미완료 또는 불확실 상태입니다. 오류가 출력돼도 전송이 이미 일어났을 수 있습니다. JSON에 나온 `no_automatic_resend`는 자동 재전송하지 않는다는 뜻이지, 전송되지 않았다는 뜻이 아닙니다.

로컬 기록의 `prepared`, `send_attempted`, `sent_confirmed`는 각각 준비 시작, 전송 버튼 누르기 직전 기록, 화면에서 전송 확인을 뜻합니다. `send_attempted`만 남으면 결과가 불확실하므로 앱에서 확인하세요.

## 문제 해결

- **연결 실패:** BlueStacks와 로컬 ADB 포트를 확인합니다. 인증을 요구하는 연결은 중단합니다. CLI는 인증 키를 생성·사용하지 않습니다.
- **한글 입력 실패:** `doctor`의 Swift·권한 상태와 BlueStacks 전면 여부를 확인합니다. 자동 권한 부여나 설치는 하지 않습니다.
- **다른 에이전트 또는 팝업:** 올바른 대화를 직접 열고 읽기부터 확인합니다.
- **초안·첨부 때문에 중단:** 기존 내용 또는 남겨진 초안을 직접 확인·정리합니다. 오류를 해결하려고 무작정 전송하지 마세요.
- **중복 요청 차단·시간 초과:** 앱과 기록에서 기존 결과를 확인합니다. 기록 삭제나 새 ID로 우회하는 재시도는 피하세요.
- **첨부·저장 UI 오류:** 파일 선택 화면이 남아 있는지 확인합니다. 새 메시지를 보내는 대신 필요한 저장 작업만 진행하세요.

새 환경에서는 비민감 자료로 진단 → 읽기 → 텍스트 전송 → 첨부 → 다운로드를 하나씩 확인하세요. Windows, Intel Mac, 다른 에뮬레이터, 다른 UI 배율·해상도와 버전은 검증하지 않았습니다.

공유 ZIP에는 상태 디렉터리, 계정 정보, ADB 키, 실제 대화, 로그, 스크린샷, 첨부 원본, 다운로드 결과를 넣지 마세요. 코드 작성과 로컬 압축만으로 외부 게시나 제3자 전송은 수행되지 않습니다.

보안·잔여 파일·클립보드 관련 주의 사항은 [SECURITY.md](SECURITY.md)를 읽어 주세요.
