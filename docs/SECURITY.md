# 보안과 개인정보 안내

이 도구는 로그인된 Pickle 앱의 화면을 조작하는 개념 검증용 CLI입니다. 실행 권한이 있는 사람은 해당 계정으로 메시지와 파일을 보낼 수 있으므로 신뢰할 수 있는 개인용 Mac에서만 사용하세요. 자동화 중에는 사람이 상태를 지켜보되 다른 입력이나 앱 조작을 하지 않아야 합니다.

## 연결과 권한

- 호스트는 항상 `127.0.0.1`이며 기본 포트는 `5555`입니다. `--port`는 로컬 포트만 변경합니다.
- ADB 데몬, 외부 수신 포트, 원격 접속, 방화벽 규칙을 켜거나 바꾸지 않습니다.
- 인증 키·토큰을 생성하거나 기존 ADB 인증 키를 읽어 사용하지 않습니다. ADB가 인증을 요구하면 중단합니다.
- BlueStacks의 로컬 ADB는 사용자가 직접 설정합니다. 필요가 끝나면 직접 끄세요.
- Swift 도구 설치나 macOS 손쉬운 사용 권한 부여는 자동으로 하지 않습니다.
- 외부 컴퓨터 연결, 포트 포워딩, 네트워크 공개는 지원하지 않습니다.

루프백 연결도 같은 Mac의 다른 프로그램이나 해당 Mac을 이용하는 사람으로부터 격리된 비밀 통로는 아닙니다.

## 데이터 이동과 기록

- `ask`의 메시지는 로그인된 계정의 Pickle 대화와 서비스로 전송됩니다.
- 첨부 파일은 Android의 작업별 Download 폴더로 복사한 다음 Pickle에 첨부됩니다. Mac 안에서만 처리되는 것이 아닙니다.
- `read`와 응답 출력에는 현재 보이는 대화 텍스트가 포함됩니다.
- 응답 파일은 Android에 저장한 후 Mac의 지정 폴더로 가져옵니다.
- 기본 상태 위치는 `~/.local/state/pickle-air-cli`입니다. `--state-dir`로 요청 기록 위치를 바꿀 수 있지만 공통 잠금 파일은 기본 위치에 남습니다.
- 요청 ID는 기록 파일명에, 해시·처리 상태·갱신 시각은 기록 내용에 남습니다. 메시지 본문이나 대화 로그를 상태 파일에 저장하지 않습니다.
- 새 상태 디렉터리는 `0700`으로 생성합니다. 이미 존재하는 폴더의 권한은 직접 확인하세요.

메시지는 명령행 인수로 전달되므로 셸 기록, 프로세스 인수, 터미널 출력과 오류 보고를 통해 노출될 수 있습니다. 요청 ID에도 개인 정보나 업무 내용을 넣지 마세요. 내용 해시는 익명화나 암호화를 보장하지 않습니다.

비밀번호, 인증 코드, API 키, 금융·의료·신분증 정보처럼 민감한 자료로 테스트하지 마세요. Pickle의 서버 보관·삭제 정책은 해당 서비스를 따르며, 로컬 파일을 지워도 이미 전송한 자료가 회수되지는 않습니다.

## Mac과 Android 클립보드

허용된 ASCII 입력은 ADB로 직접 처리합니다. 한글·이모지·줄바꿈 또는 직접 입력 범위 밖 문자는 Swift/AppKit과 기존 손쉬운 사용 권한을 이용합니다.

- Mac의 기존 클립보드 형식과 내용은 메모리에 보관하며 파일로 저장하지 않습니다.
- 정상 종료 시 CLI가 넣은 클립보드가 그대로인 경우에만 이전 내용을 복원합니다.
- 사용자가 새로 복사했거나 다른 프로그램이 클립보드를 변경했다면 그 새 내용을 덮어쓰지 않습니다.
- 강제 종료, 충돌, 시스템 종료 시 복원이 끝나지 않을 수 있습니다.
- **Android 에뮬레이터 클립보드는 제출할 텍스트로 바뀌며 원래 내용으로 복원하지 않습니다.**
- 클립보드 기록 프로그램이나 기기 간 동기화가 임시 텍스트를 보관·전달할 수 있습니다.

Mac 클립보드를 복원해도 Android나 클립보드 관리 앱에 남은 내용까지 지워지는 것은 아닙니다.

## 전송 안전장치와 한계

- 같은 포트의 `read`·`ask`·`download`는 공통 잠금으로 직렬화합니다. 별도의 상태 폴더를 지정해도 같은 CLI의 동시 조작을 차단합니다.
- 기존 초안·첨부가 있으면 `ask`를 시작하지 않습니다. 오류 중 생긴 초안·첨부는 확인할 수 있도록 남을 수 있습니다.
- 요청 기록이 있으면 같은 요청 ID를 다시 실행하지 않습니다.
- 전송 버튼을 한 번만 누르고 자동 재전송하지 않습니다. `send_attempted` 상태를 버튼 누르기 전에 저장합니다.
- 화면에서 확인한 전송·응답 상태는 공식 서버의 전송 ID나 완료 이벤트가 아닙니다.

기록을 지우거나 다른 기기·상태 폴더·새 ID를 사용하면 중복 방지가 이어지지 않습니다. 전송 직후 중단되면 실제 결과가 불확실할 수 있습니다. **모를 때는 재전송하지 말고 앱 화면을 먼저 확인하세요.**

공통 잠금은 사람의 입력과 다른 자동화 도구까지 막지 않습니다. 대상 에이전트, 입력창, 화면 전면 상태를 사용자가 확인해야 합니다.

## 첨부 파일 검증의 범위

최대 4개, 파일당 8 MiB의 일반 파일만 받습니다. 허용 확장자는 PNG/JPG/JPEG/TXT/PDF/CSV이며, 확장자 검사는 악성 파일 검사나 형식 검증이 아닙니다. 실제 첨부 확인은 PNG·TXT에 한정합니다.

파일을 작업별 Android 폴더에 복사하고 해시를 비교한 뒤, 정확한 파일명을 기본 선택기에서 찾아 고릅니다. 전송 전에는 첨부 개수를 다시 확인합니다. 파일명에는 순번을 붙이며 안전한 ASCII 규칙을 벗어난 원래 이름은 일반 이름으로 바뀝니다.

**최종 첨부 표시에서 파일명을 읽을 수 없으므로 최종 첨부의 정체성까지 검증하지 못합니다.** 같은 개수를 유지한 채 파일이 바뀌는 동시 조작이나 모든 업로드 진행 상태를 탐지하지 못합니다. 민감한 전송이나 중요한 제출에는 사용하지 마세요.

## 잔여 파일과 다운로드

- Android의 `Download/pickle-cli-…` 작업 폴더에 첨부와 중간 Base64 파일이 남습니다.
- 다운로드 시 Android에 만든 `pickle-response-…` 복사본도 남습니다.
- 자동 정리는 하지 않습니다. 사용자가 앱에서 작업이 끝났는지 확인하고 필요한 항목만 직접 정리해야 합니다.
- 앱 캐시나 최근 파일 목록에도 흔적이 남을 수 있으며 완전 삭제를 보장하지 않습니다.
- 다운로드 파일명은 제한된 ASCII 이름만 허용합니다. 로컬에 같은 이름이 있으면 덮어쓰지 않습니다.
- 다운로드 상한은 16 MiB입니다. 크기·해시 안정성과 복사 후 일치 확인은 구현되어 있지만 모든 저장 지연·앱 버전에 대한 보장이 아닙니다.
- 출력 폴더는 접근을 관리하는 위치로 정하세요. 공용·동기화 폴더는 다른 사람에게 파일을 노출할 수 있습니다.
- 받은 파일은 신뢰할 수 없는 입력으로 취급하고 스크립트·실행 파일·매크로를 자동 실행하지 마세요.

## 안전하게 공유하기

공유 ZIP에는 소스, 문서, 비민감 합성 테스트만 포함하세요. 받는 사람은 자신의 계정·설정을 사용합니다. MIT 라이선스의 재배포 조건에 따라 LICENSE도 포함하세요.

다음은 제외하세요.

- 계정·암호·쿠키·세션·토큰·ADB 키
- 실제 대화·화면 캡처·로그·진단 출력
- 상태 디렉터리·요청 기록·개인 설정
- 첨부 원본·다운로드 결과·Android 작업용 파일
- 개인 사용자명·파일 경로가 드러나는 불필요한 자료

패키지 제작은 공개 게시나 외부인 전송을 뜻하지 않습니다. 사용자가 공유 여부와 대상을 결정하기 전에는 저장소·패키지 레지스트리·파일 공유 사이트에 자동 공개하지 않습니다.

## 문제 보고

이 패키지에 검증된 공개 보안 신고 채널은 정해져 있지 않습니다. 공유받은 경로의 담당자에게 먼저 문의하세요.

재현 단계, 운영체제·BlueStacks 버전, 명령 이름, 민감 정보를 제거한 오류만 전달하세요. 실제 메시지·첨부·전체 기록·인증 정보는 보내지 마세요. 화면 캡처가 필요하면 대화·계정명·개인 경로를 가리세요.

공식 API 지원, 무인 운영, 모든 버전 호환, 정확히 한 번 전송, 완전한 복원·삭제를 보장하지 않습니다. 계정 정보나 민감한 자료가 잘못 전송됐다고 의심되면 실행을 멈추고 해당 서비스에서 직접 확인하세요. CLI가 메시지를 자동 회수하거나 삭제하지는 않습니다.
